# Design Brief — "I Yearn For Your Sweet TD's" Keeper Dashboard

*Prepared for a design polish pass. Self-contained: you should be able to work from this without the codebase. Companion file: `design_trade_analyzer_mockup.html` (open in a browser).*

---

## 1. What this is

A single-page dashboard for a 12-team Yahoo fantasy football **keeper** league. It helps the 12 managers see, for the upcoming 2026 season:

- each team's **keeper costs** under the league's custom "DRC" system (a Draft-Round-Cost model where a lower DRC number = a more expensive keeper),
- **draft history** per team,
- **trades** (with production outcomes), and
- a **trade analyzer** to model a proposed deal.

Live site: `https://hodorpete-925.github.io/IYearnForYourSweetTD-s/`
Viewed on **desktop and mobile**.

The current site is clean and functional — this pass is about **polish and a more visual trade analyzer**, not a rebuild.

---

## 2. Technical reality (please read — it shapes how to hand work back)

- The whole site is **one self-contained HTML file** (`dashboard.html`): inline `<style>`, inline `<script>`, no external CSS/JS libraries for layout.
- That file is **generated by a Python script** (`generate_dashboard.py`) which builds the HTML as templated strings and injects data from a database. **The source of truth is the Python generator — never hand-edit `dashboard.html`** (it gets overwritten on every rebuild).
- Because content is templated from data, design **reusable components**, not one-off hardcoded screens.
- **No browser storage** (localStorage/sessionStorage) — the page is static/generated.
- Keep everything **offline-safe**: system fonts, inline SVG/CSS. (If a chart truly needs a library, Chart.js from CDN is tolerable, but prefer inline.)

## 3. Design system (current — please stay within it)

**Color tokens** (CSS variables in `:root`):

| Token | Hex | Use |
|---|---|---|
| `--blue-800` | `#022479` | Primary. Sidebar bg, headers, key numbers |
| `--blue-600` | `#0038FF` | Accent, links, deltas |
| `--blue-400` / `--blue-200` | `#269AFF` / `#77CEFF` | Light accents on dark |
| `--gold-400` | `#E1B523` | Highlight / award |
| `--gray-700 → --gray-50` | `#2a2a2e … #fcfcfd` | Text, borders, fills |
| *(suggested additions)* | green `#1c7a4a`/`#e6f6ee`, red `#b42318`/`#fdecea` | success / problem states (used in the mockup) |

**Type:** system stack — `-apple-system, BlinkMacSystemFont, "Inter", "Helvetica Neue", Arial`. Body 14.5px / line-height 1.55. Micro-labels are ~10–11px, uppercase, letter-spaced, gray.

**Layout:** 280px **sticky sidebar** (`--blue-800`) + fluid content. Cards = 1px `--gray-200` border, ~8–9px radius. Tables use `tabular-nums`, uppercase column micro-labels, subtle 1px row separators.

**Aesthetic:** clean, editorial / **financial-report**. Restrained, data-forward, generous whitespace. No heavy shadows or gradients.

**Responsive:** must work down to ~720px; the sidebar stacks/collapses on mobile.

## 4. Areas to improve

### 4.1 Trade analyzer — the headline change *(see the mockup)*

**Problem today:** it's text-heavy — results read as prose and there's a long paragraph of assumptions at the bottom. Managers want to *see* the trade, not read it.

**Target:** table-driven and scannable. Open `design_trade_analyzer_mockup.html` for the full concept. It contains:

1. **Team pickers** (A ⇄ B) — compact, each showing the team, manager, and current cap.
2. **Current rosters** — two side-by-side tables **sorted by DRC ascending** (most expensive keeper first), matching the existing team-roster table style: `Player · Pos · DRC chip · Cost · 2025 pts`. Players being traded are **highlighted (red tint) with a "TRADE →" tag**.
3. **The trade** — a compact center strip showing what moves each way with points/DRC, plus the **production swing**.
4. **After the trade** — two tables showing each team's resulting roster with:
   - the **incoming player slotted** at their frozen-2026 DRC (green "IN" highlight),
   - each keeper's **draft slot** (R1, R2…),
   - the **new cap** as `before → after` with a colored **▲/▼ delta**,
   - and — the important one — **red flags on any keeper who becomes un-keepable** (a "chasm": no owned draft round to slide into), with a short callout explaining why and what would fix it.
5. **Assumptions** — collapsed into a small footer, not a wall of text.

**Visual language to establish:** DRC **tier chips** (color-coded by tier), **red = problem/un-keepable**, **green = incoming/clean**, ▲/▼ for cap direction.

### 4.2 Player search card — newest-first ordering

**Problem:** the per-year blocks (DRC over time, Performance & market / ADP, Weekly fantasy points, position-rank neighbors) currently run **oldest → newest** left-to-right (2023, 2024, 2025).

**Target:** **reverse to newest-first** — the most recent year on the **left**, older years to the right — **consistently across every metric row and table in the card**. Keep the tile and mini-bar styling; only the column order changes. Rationale: the current/most relevant season should be the first thing the eye lands on.

### 4.3 Draft page (per-team "Drafts" tab)

**Current:** a per-year table with round-banded rows, pick labels (e.g. `1.07`), keeper / "Traded for" tags, a **DRC trajectory** string (e.g. `R6 (2023) → 5 → 4`), a value-vs-ADP pill, and a hover tooltip holding the transaction log.

**Direction (please view the live page):** reduce visual noise and sharpen hierarchy — clearer **year grouping/headers**, make the **DRC trajectory** read as a compact chip sequence rather than inline text, make the **value pills** consistent with the rest of the site, and make the **hover tooltip** more discoverable (it's easy to miss that rows are interactive). Goal: a manager can scan a team's draft history and instantly see who's a keeper, at what cost, and how that cost has moved.

### 4.4 Navigation — getting home

**Current:** a 280px sticky sidebar lists teams and a league summary/home.

**Target:** an obvious, always-available way **back to the league home/summary** from any team page or the trade analyzer — e.g. a clickable title/logo in the sidebar header, a persistent "← League home" affordance at the top of the content column, and a **back-to-top** on long pages. Make sure home stays reachable on **mobile** when the sidebar collapses.
